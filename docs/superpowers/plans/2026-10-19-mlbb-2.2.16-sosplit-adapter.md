# Mobile Legends: Bang Bang v2.2.16.12322 SOSplit Adaptation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Adapt Android-LibTool-New (`app`) to support Mobile Legends: Bang Bang v2.2.16.12322 (`dump_mlbb`) by supporting its multi-library SOSplit architecture (`libcsharp.so`, `liblogic.so`, `libfirst.so`, `libil2cpp.so`), multi-metadata layout, dynamic HybridCLR assembly loading, and combat metadata string navigation.

**Architecture:** Replace single-library assumptions (`targetLibName` = `"libil2cpp.so"`) with dynamic multi-module address resolution using `dladdr` and runtime memory maps. Add an assembly lifecycle watcher and manual refresh trigger for `Assembly-CSharp.dll` (loaded dynamically by HybridCLR). Update code generation for Dobby and GameGuardian scripts to target the correct split `.so` module. Add a Combat Strings Explorer tab powered by the extracted patch metadata. Ensure 16KB page alignment and Android 16 compatibility.

**Tech Stack:** C++17, Android NDK (r27), Dobby Hook, Frida Gum, ImGui, xDL, nlohmann/json, Gradle 7.2.

**Spec:** Analysis of `New patch update Mobile Legends_ Bang Bang_2.2.16.12322/dump_mlbb` and `app/src/main/jni`.

## Global Constraints

- Target package: `com.mobile.legends` (Version: `2.2.16.12322`, VersionCode: `211812322`).
- Target ABI: `arm64-v8a` (with backwards compatibility for `armeabi-v7a`).
- NDK Version: `27.0.12077973` with C++17 (`-std=c++17`).
- Android 16 compatibility: Must build with 16KB ELF page alignment (`-Wl,-z,max-page-size=16384`).
- Memory safety: No unhandled null pointer dereferences when iterating delayed/dynamic assemblies.

## Review Focus

1. **SOSplit Module Resolution:** `methodPointer` resides in `libcsharp.so` or `liblogic.so`, not `libil2cpp.so`. Resolving offset against `libil2cpp.so` yields an invalid or negative offset; resolver must identify module name and base dynamically.
2. **Late Assembly Registration:** `Assembly-CSharp.dll` (20,003 types) is loaded by MLBB's `GameLoader` after the 30s startup timeout. The tool must gracefully handle late loads without crashing and allow refreshing loaded assemblies.
3. **HybridCLR Method Invocation:** HybridCLR interpreted/AOT hybrid methods may have null or bridge `methodPointer` values. Tracer and patcher must check `method->methodPointer != nullptr` before applying native hooks.
4. **Android 16 Page Size & W^X:** Android 15/16 enforces strict W^X and 16KB page alignment. In-memory patching via KittyMemory/Dobby must properly align `mprotect` calls to system page size (`sysconf(_SC_PAGESIZE)`).
5. **Combat Metadata Strings:** Searching strings in `System.String` GC heap misses compile-time literals; pre-extracted JSON metadata (`mlbb_extracted_strings.json`) must be accessible offline for quick navigation.
